# Shadow Clone - 智能影子分身协作看板

## 项目愿景

> **"当主角不在时，影子替他战斗。"**

Shadow Clone 是一个智能化的个人影子分身协作系统。核心价值在于：当项目负责人不在或忙碌时，协作方可以通过这个看板提交任务需求，影子分身（基于Claude Code）会自动接收任务、在本地工作目录执行、并将结果返回给看板，形成一个闭环的自动化协作流程。

---

## 核心概念

### 1. 影子分身 (Shadow Avatar)
- 本质是部署在本地机器上的 Claude Code 实例
- 具备主人的工作上下文、偏好设置和技能树
- 24/7 待命，随时响应看板任务

### 2. 协作看板 (Collaboration Board)
- 任务入口：任何需要影子分身协助的人都可以创建任务
- 状态追踪：实时显示任务在各阶段的进度
- 结果展示：Claude Code 的工作成果直接展示在看板上

### 3. OpenKit 通信协议
- 标准化任务下发格式
- 双向实时通信
- 结果回传机制

## 用户故事

### 场景一：远程协作
**角色**：外部协作者小王
**场景**：小王需要主程序员张三的帮助解决一个技术问题，但张三正在开会
**流程**：
1. 小王访问 `http://zhangsan.local:3000` 打开影子分身看板
2. 点击"新建任务"，填写问题描述和技术栈
3. 提交后，任务卡片出现在"待领取"列
4. 张三的 Claude Code 自动检测到新任务（通过本地轮询/WebSocket）
5. Claude Code 领取任务，开始分析并解决问题
6. 解决完成后，结果链接（GitLab MR/PR）显示在卡片上
7. 小王收到通知（可选），查看结果

### 场景二：方案快速生成
**角色**：产品经理李四
**场景**：需要影子分身快速生成一个技术方案文档
**流程**：
1. 李四创建任务，选择类型"方案设计"
2. 填写需求背景、约束条件、期望交付物
3. 提交后，Claude Code 在本地工作目录创建方案文档
4. 文档自动提交到 GitLab 仓库
5. 看板上显示文档链接，任务标记为"已完成"

### 场景三：代码审查请求
**角色**：团队成员王五
**场景**：需要影子分身帮忙 review 一段代码
**流程**：
1. 王五创建任务，选择类型"代码审查"
2. 上传或粘贴代码片段，指定审查重点
3. Claude Code 领取后进行深度代码审查
4. 审查报告生成并链接到任务卡片

## 功能需求

### F1: 任务管理

#### F1.1 创建任务
- **输入字段**：
  - 任务标题（必填，50字以内）
  - 任务类型：技术问题 / 方案设计 / 代码审查 / 其他
  - 优先级：低 / 中 / 高 / 紧急
  - 详细描述（必填，支持 Markdown）
  - 技术栈标签（可选，多选）
  - 截止日期（可选）
  - 附件上传（可选，支持代码文件、文档、图片）
  - 期望交付物（可选）

#### F1.2 任务状态流转
```
[新建] → [待领取] → [处理中] → [已完成] / [需要反馈] → [已关闭]
```

- **新建**：用户刚创建，尚未提交
- **待领取**：已提交，等待影子分身认领
- **处理中**：影子分身正在处理
- **已完成**：任务完成，结果已返回
- **需要反馈**：任务完成但需要人工确认
- **已关闭**：任务完结，不再处理

#### F1.3 任务卡片展示
- 任务标题 + 类型标签
- 优先级指示（颜色编码）
- 创建者头像/名称
- 创建时间
- 当前状态 + 状态变化时间
- 处理时长
- 结果链接（完成后显示）
- 快速操作按钮

### F2: 看板视图

#### F2.1 列定义
- **待领取**：所有新建并提交的任务
- **处理中**：正在被影子分身处理的任务
- **已完成**：结果已返回的任务
- **已关闭**：归档的任务

#### F2.2 看板交互
- 拖拽任务卡片（可选，简化版可跳过）
- 点击卡片展开详情
- 筛选器：按类型、优先级、创建者、时间范围
- 搜索：按标题、描述关键词搜索
- 排序：按创建时间、优先级、处理时长

### F3: 影子分身状态

#### F3.1 在线状态指示
- 🟢 在线：Claude Code 正在运行，可接收任务
- 🟡 忙碌：正在处理任务
- 🔴 离线：未运行或未连接
- ⚪ 未知：状态检测中

#### F3.2 影子分身控制
- 启动/停止影子分身
- 查看当前处理的任务
- 查看任务处理历史
- 设置自动领取模式

### F4: 通知系统

#### F4.1 通知类型
- 新任务创建通知（给主人）
- 任务状态变更通知（给创建者）
- 任务完成通知（给创建者）
- 紧急任务提醒

#### F4.2 通知方式
- WebSocket 实时推送（看板内）
- 邮件通知（可选）
- Webhook 回调（可选）

### F5: OpenKit 集成

#### F5.1 任务下发协议
```json
{
  "task_id": "uuid",
  "type": "code_review",
  "priority": "high",
  "title": "Review login module",
  "description": "...",
  "attachments": ["file1.py"],
  "expected_delivery": "review_report.md",
  "callback_url": "http://board/openkit/callback",
  "metadata": {
    "requester": "xiaowang",
    "created_at": "2025-05-09T10:00:00Z"
  }
}
```

#### F5.2 结果回传协议
```json
{
  "task_id": "uuid",
  "status": "completed",
  "result": {
    "type": "gitlab_mr",
    "url": "https://gitlab.example.com/.../merge_requests/123",
    "commit_sha": "abc123"
  },
  "summary": "Code review completed. Found 3 issues.",
  "completed_at": "2025-05-09T10:30:00Z"
}
```

### F6: Claude Code 插件

#### F6.1 核心能力
- 监听看板任务（通过本地 API / WebSocket）
- 智能任务分析
- 上下文理解与检索
- 代码执行与修改
- GitLab 集成（创建 MR、提交代码）
- 结果报告生成

#### F6.2 交互命令
- `/shadow help` - 显示帮助
- `/shadow status` - 查看分身状态
- `/shadow tasks` - 查看待处理任务
- `/shadow take <task_id>` - 领取任务
- `/shadow done <task_id>` - 完成任务
- `/shadow cancel <task_id>` - 取消任务

### F7: GitLab 集成

#### F7.1 功能
- 创建 Merge Request
- 提交代码变更
- 创建/更新文档
- 评论和讨论

#### F7.2 配置
- GitLab URL
- Access Token（Personal Access Token）
- 默认项目
- 仓库路径映射

### 技术栈选型

#### 前端
- **框架**：Next.js 16 (App Router)
- **UI 库**：基于 Tailwind CSS 4 + 自定义组件
- **状态管理**：React Context + useReducer
- **动画**：Framer Motion + GSAP
- **图标**：Lucide React
- **拖拽**：@dnd-kit/core
- **WebSocket**：原生 WebSocket + 重新连接逻辑

#### 后端
- **运行时**：Node.js 20+
- **框架**：Next.js API Routes
- **数据库**：SQLite（本地，轻量）
- **ORM**：Better SQLite 3
- **实时通信**：WebSocket (ws library)

#### Claude Code 插件
- **运行环境**：Claude Code 原生插件系统
- **通信**：HTTP + WebSocket 双通道
- **执行**：Node.js
